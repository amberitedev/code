Upstream baseline · Human understanding sheet

Modrinth, reduced to its product model.

Modrinth is a Minecraft: Java Edition content platform joined to a desktop launcher, creator economy, multiplayer directory, and managed hosting product. One catalog and identity system connects all of those surfaces.

Product promise

Make community-made Minecraft content easy to find, trust, install, play, publish, and maintain.

What this sheet is

A short mental model for deciding what Amberite inherits, changes, or removes (not an implementation specification).

01 · Surfaces

One platform, several jobs

Website (catalog and creator platform)

Public discovery, project pages, profiles, collections, publishing, team management, analytics, revenue, account settings, and browser-based server management.

App (launcher and local manager)

Creates isolated Minecraft installations, installs and updates content, manages local play state, launches the game, and exposes Hosting inside the desktop experience.

Hosting (remote runtime)

Runs paid Minecraft servers and provides setup, content, console, files, worlds, backups, networking, settings, and permissioned collaboration.

Server directory (multiplayer discovery)

Turns a live server into a public project with an address and compatibility requirements (separate from buying Hosting).

API and delivery layer (shared infrastructure)

Powers Modrinth surfaces and third-party tools with catalog metadata, authenticated actions, and file delivery.

02 · Loop

The main player loop

DiscoverSearch a shared catalog.
DecideRead trust and compatibility data.
InstallResolve the correct content into an instance.
PlayLaunch locally or join a compatible server.
MaintainUpdate, change, follow, or share.
The creator loop mirrors it: create a project → publish a compatible release → pass review → gain discovery → read analytics and revenue → publish again.
03 · Model

The nouns everything is built around

Modrinth account
Owns platform identity, projects, follows, collections, permissions, purchases, and creator data.
Minecraft account
Provides the game entitlement and player identity used when the App launches Minecraft.
Project
The stable public identity of a creation across releases, loaders, and game versions.
Version
A release with files, compatibility, dependencies, environment rules, and a change description.
Instance
An isolated local Minecraft installation containing its own content, configuration, worlds, and logs.
Collection
An editable cloud list of project references (not an installable modpack).
Team or organization
The ownership and permission layer used to operate one or more creator projects.
Hosting server
A cloud-owned running server with operational state and collaborators (not a public server project).
04 · Rules

Decisions that make the system coherent

Compatibility is behavior. Game version, loader, dependencies, and client/server environment decide what can be installed.
Project, version, and file stay separate. Identity, release intent, and downloadable bytes have different lifecycles.
Local and cloud state stay separate. App instances live on a device; account data and Hosting state live on the platform.
The catalog is shared. Website, App, Hosting, API users, and creator tooling operate on the same content model.
Public consumption is broad. Reading and downloading are mostly open; private state, publishing, collaboration, and purchases require identity.
Trust is part of publishing. Validation, moderation, malware checks, licensing, attribution, reports, and takedowns govern public content.
Linking preserves intent. A linked instance follows a project or server requirement; unlinking turns it into independent local state.
Similar screens do not merge authority. Local instances and hosted servers share management patterns while keeping different owners and persistence.
05 · People

Who the product is designed for

Player

Finds content, keeps local instances healthy, follows projects, manages Minecraft identity, and joins compatible multiplayer servers.

Creator

Publishes projects and releases, works with a team, responds to review, and uses analytics and revenue tools.

Server operator

Provisions and runs a remote server, installs content, manages runtime state, and grants limited operational access.

Moderator

Reviews submissions, resolves reports and rights concerns, communicates required changes, and protects the catalog.

API integrator

Builds launchers, publishing tools, or connected services on the public catalog and scoped account actions.

06 · Shape

What makes the experience feel like Modrinth

Project-first navigation. Search results lead to a durable page, then to compatible releases and actions.
Context-aware actions. Install choices depend on the current instance, account, platform, and compatibility.
Progressive detail. Common actions stay simple while versions, files, dependencies, settings, and diagnostics remain reachable.
Cross-surface parity. Content and server management are intentionally becoming consistent between App and website.
Utility-led community. Profiles, follows, collections, notifications, teams, organizations, and friends support play and publishing rather than forming a full social network.
Sustainable exchange. Hosting, subscriptions, and advertising fund the platform while eligible creators receive a share.
Amberite inherits more than a visual shell. It inherits Modrinth’s catalog vocabulary, compatibility logic, local-instance model, account boundaries, creator surfaces, and hosting-shaped management UX. The final product document must explicitly keep, replace, or remove each of those domains.
