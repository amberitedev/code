# src/api — Tauri Command Plugins

Each module is a Tauri plugin registered via `api::<name>::init()` in `main.rs`. All commands return `api::Result<T>` = `Result<T, TheseusSerializableError>`, which serializes to `{field_name, message}` on the JS side. Error type and serialization macro live in `mod.rs`.

Frontend does **not** use these commands to talk to `apps/core`. Core communication goes via `tauriFetch` (HTTP) through `@amberite/api-lib`. These plugins cover the Minecraft engine (`theseus`) and local app concerns only.

## Module-Specific Gotchas

**`auth`** — `login` returns `Option<Credentials>`. User closing the MSA WebviewWindow = `Ok(None)`, not an error. Always check for `None` before treating the response as success.

**`mr_auth`** — Opens the system browser and spins up a loopback HTTP server to catch the redirect. `cancel_modrinth_login` is the only way to abort. The OAuth flow is implicit grant — the `?code=` redirect parameter IS the session token. No PKCE (known TODO).

**`settings`** — `settings_set` is a full replacement, not a partial patch. Always read current settings first, merge, then write.

**`cache`** — Commands are auto-generated by the `impl_cache_methods!` macro. To find what commands exist, read the macro definition — the module source itself shows only the macro invocation.

**`process`** — `profile_run` returns `ProcessMetadata`, not a handle. Monitor the running process via `listen("process")` and `listen("log")` Tauri events, not the return value.

**`amberite/`** — Only 4 commands: `ping`, `get_local_core_token`, `is_core_running`, `core_get_url`. All actual Core API calls bypass this and go via `tauriFetch` directly. Do not add per-endpoint proxies here.

**`oauth_utils/`** — `pub(crate)` only. Do not expose further.
